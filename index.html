강점 / 취향

  1. 팀 협업 속 백엔드 설계

    상황
    SevMerge 팀 프로젝트에서 4명이 동시에 백엔드를 개발해야 했습니다.
    행동
    GitHub Flow를 제안해 PR 리뷰 문화를 만들고, API 명세서를 먼저 작성해 충돌을 줄였습니다.
    결과
    7인 팀이 기능 충돌 없이 병렬 개발을 완료하고 프로젝트를 기간 내 마쳤습니다. ↗ GitHub 확인

  2. 오류 원인을 끝까지 찾는 습관

    상황
    Spring Security + JWT 구현 중 토큰 만료 후에도 인증이 통과되는 버그가 발생했습니다.
    행동
    공식 문서로 필터 체인 실행 순서를 분석하고, 만료 검사 필터 위치가 잘못된 것을 확인해 수정했습니다.
    결과
    인증 오류 0건으로 블로그 API 완성. 이후 Security 필터 순서를 먼저 설계하는 습관이 생겼습니다.

  3. 직접 만들며 배우는 자기주도 학습

    상황
    백엔드 위주 공부로 프론트엔드 기초가 부족해 협업 시 소통이 어렵다고 느꼈습니다.
    행동
    React 없이 Vanilla JS만으로 이 포트폴리오를 직접 구현했습니다. 모달·필터·IntersectionObserver·접근성까지 적용했습니다.
    결과
    DOM 조작 원리를 이해하고, 백엔드-프론트 연결 흐름을 한층 구체적으로 그릴 수 있게 됐습니다.
